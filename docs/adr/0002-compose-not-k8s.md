# ADR 0002: Docker Compose stacks now, Kubernetes later

Date: 2026-09-07. Status: accepted.

## Context
Workloads are a handful of game servers, an LLM (large language model) API and UI, and monitoring, all on one node. Every game server image documents itself as a compose file. Kubernetes is interesting for learning but adds an API server, CNI (Container Network Interface) plugins, ingress and storage layers that a single box does not need.

## Decision
Enable Docker in NixOS (rootful; see ADR 0006 for why, and how its risks are handled) and run each service as a Compose stack wrapped in a systemd unit generated by a small reusable NixOS module. Stack files live in the repo and deploy through the same GitOps path as the OS. K3s is a stretch phase (Phase 8) with an explicit go/no-go once the base is stable.

## Consequences
- Upstream compose files can be used almost verbatim.
- Restart ordering, resource limits and logging come from systemd, not a second orchestrator.
- No rolling updates or self-healing across nodes; irrelevant with one node.
- Migrating to K3s later is a per-stack job, so nothing is blocked.
